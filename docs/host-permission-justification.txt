Winnow analyses reviews on Amazon product pages, so it must read those pages. The content script reads the already-rendered rating, rating histogram and visible reviews, scores them locally, and injects a results panel. Access is limited to Amazon storefront domains. Winnow requests no other site and does not use "tabs".

The content script itself makes no network requests, so nothing read from an Amazon page is sent anywhere. The extension does contain one network path, and this permission is not it: when a sponsor is configured, the background worker fetches a sponsored message for Winnow's own toolbar popup and settings page. That request carries a schema version, which of the two windows asked, and the formats it can draw - no page address, no product, no grade and no identifier. It is drawn only in Winnow's own windows and never appears on an Amazon page. No sponsor is configured in this version, so this build makes no such request and carries no advertising host permission at all.

The optional localhost/127.0.0.1 permission is not requested at install and is unused by the published extension. Winnow's engine and its optional server are open source; a developer running that server locally can point the extension at it from the options page. That is the only time it is requested, by explicit user action via chrome.permissions.request. Only loopback addresses are accepted; anything else is rejected and never stored, and the service worker independently refuses any non-loopback endpoint. A normal install never holds it and never contacts anything.
